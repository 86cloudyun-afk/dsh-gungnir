# ADR-004 v0.2 冻结边界与验收

- 状态：Accepted（2026-10-02）
- 关联：[WARROOM-FRAMEWORK.md](../WARROOM-FRAMEWORK.md) §12；[ACCEPTANCE.md](../ACCEPTANCE.md)
- 前置：v0.1 冻结闭环已合并（tag `v0.1.0-alpha.3` + 批次 3 待合并）。

## Context

v0.1 交付了：事实库（成员级幂等/水位/迁移）、门闸（四元组/授权对象/节奏/批准）、
秘密边界、报告（水位 + IOC 自动聚合 + 复现校验）、跳板池、adapter 三实现（fake/local/bridge）
与一致性套件、CLI、部署脚本、五道 CI 闸。

仍缺（见 ACCEPTANCE「缺口」表）：
1. 桶 A 围栏的**真实运行验收**（拓扑与脚本就绪，本机 docker daemon 未运行 → SKIP）
2. **进程级取消证实**（当前为会话/清单级探针）
3. **知识库**（POC/EXP 跨战役复用与回填脱敏）
4. **真实执行层接入**（应答器 echo 分支需替换为调红队模式插件服务）

## Decision

**v0.2 只做上述四项，且每项给出可复跑的验收判据**：

| 项 | 判据 |
|---|---|
| 围栏运行验收 | 在带 docker daemon 的 runner 上 `node scripts/fence-verify.mjs …` 输出 `passed`；CI 中若 daemon 不可用则记 SKIP（不得视为通过） |
| 进程级取消证实 | 执行层上报每资源进程标识（pid/cgroup/容器 id）；`confirmed_stopped` 要求探针实测这些标识不存在；提供「会话已停但子进程仍在」的负样本 |
| 知识库 | 全局 `knowledge.db`：POC 条目（code/来源/影响版本/验证证据）+ 14 类归类；**跨战役复用**；回填强制脱敏（内网地址/自有 VPS 正则审计）；跨战役复用的回归测试 |
| 真实应答器 | `handleJob` 调红队模式插件服务；端到端演练：真实派单一角色 → 事实经桥入库 → 报告可复现 |

**明确不做**（避免范围蔓延）：
- UI 控制台 → v0.3（当前 CLI + 报告已够用）
- marketplace 上架 → v0.3（等 v0.2 四项验收全绿）
- PentAGI 接入 → **不做**（评估结论：其价值被红队模式 + 本框架覆盖，集成成本高于收益）

## Consequences

- 正面：范围收敛且每项有可复跑判据；v0.1 已完成的部分不再返工。
- 代价：围栏真实验收依赖 CI runner 的 docker 能力（GitHub Actions 默认提供 docker，
  需在 workflow 显式启用并在 daemon 不可用时标记 SKIP 而非通过）。
- 风险：进程级探针依赖执行层配合（红队模式侧需要暴露进程标识）——若不可得，
  该验收项降级为「清单级 + 人工确认」，并在 ADR 修订中显式记录。

## 验收记录方式

每项完成时在 [ACCEPTANCE.md](../ACCEPTANCE.md) 更新对应行（状态 + 证据命令 + 结果），
并在 `docs/MERGE-REVIEW-*.md` 留合并批次记录。规格改动走新 ADR，不修改本 ADR。
