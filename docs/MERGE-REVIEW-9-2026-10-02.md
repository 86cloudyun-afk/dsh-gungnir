## 本批自查记录（如实）

- **纪律违规一次**：PR71 首推时命令链用了 `grep 'not ok'` 的退出码当门禁，导致"有失败仍继续推送"。
  已在该 PR 追加修正注释并在本批修掉根因（PR72 的单命令门禁）。**教训进化为机制。**
- **测试逼出四个真问题**（不是断言写错，是代码有暗坑）：
  1. 知识库用量 SQL JOIN 写错表名（`pocs` → `poc`）；
  2. `addPoc` 静默丢弃未知字段（传错字段名的证据会静默消失）；
  3. 桥接 adapter 的 `manifestOf` 只依赖应答器文件（未回报时清单为空，违反 ADR-003）；
  4. 桥接 adapter 的"未证实"检查一次性绑定 false（应延迟绑定）；
  5. 应答器 fixture 模式缺夹具静默返回空资源（改为报错留痕）。
- `JumphostManager` 跨战役巡检原依赖 global 的 engagements 表（不存在）→ 改为宿主注入战役清单。
